The brief, in one line: the application stays simple — the network is the project. A client types a private domain name, that name is resolved by our own DNS server, the connection is secured by a certificate from our own certificate authority, and the request is load balanced across two backend machines — with packet-level evidence for every layer.

What happens in one request

  1. DNS — application layer, UDP/53 The client asks Mac 1 for app.paradise.test and is given the edge's address. A directory lookup, not a connection — nothing has contacted the edge yet.
  2. TCP — transport layer Three-way handshake from an ephemeral port to 10.7.31.205:443. Completes before a single TLS byte is sent.
  3. TLS — session / presentation ClientHello with SNI, ServerHello, key exchange. TLS terminates at the edge, using a certificate signed by our own local CA — validated with no -k flag.
  4. HTTP — application layer nginx decrypts and makes a separate, plaintext request over its own TCP connection to whichever backend round robin selects. The X-Backend header rides back untouched.

Two connections, not one. The client↔edge leg is encrypted; the edge↔backend leg is plaintext on the trusted LAN, with its own ports and its own handshake. That is why a packet capture shows opaque Application Data on one side and fully readable HTTP on the other.

What we built

All seven mandatory Phase 1 tasks, each with terminal evidence.

CTwo backendsOne Express codebase, two instances differing only by environment; every response carries X-Backend
DReverse proxy + LBnginx round robin with passive health checks, so a stopped backend never surfaces a 502
EHTTPS / TLSLocal CA, leaf certificate with a SAN, trusted on every Mac — demonstrated without -k
FHTTP cachingCache-Control: max-age=60 + ETag, with a deterministic 304 Not Modified
GPacket evidenceWireshark captures of the DNS query, the TCP handshake and the TLS handshake

One design decision worth reading about. /api/status must name the backend that answered, so our two replicas compute different ETags for the same resource. Behind round robin that makes conditional requests non-deterministic — a 304 only about half the time. We added /api/cacheable, whose body is byte-identical on both machines, so revalidation always works. Cache validators must agree across replicas, or conditional requests silently degrade into full responses.
